09 — z-index (stacking order)

Default: later HTML elements go on TOP

No z-index set. The green box (last in HTML) is on top.

A (first in HTML)
B
C (last → on top)

With z-index: YOU decide who's on top

A has z-index 3, B has 2, C has 1. Now A is on top.

A (z: 3)
B (z: 2)
C (z: 1)

⚠️ z-index DOES NOTHING without position!

A has z-index: 9999 but no position, so it's ignored.

A (z: 9999, no position)
B (no z-index)

Fix: add position: relative (or absolute/fixed/sticky).

🤯 The stacking context trap

The pink box has z-index: 9999 but it's still BELOW the blue box. Why?

Because the pink box lives inside group-one (z-index: 1) and the blue box lives inside group-two (z-index: 2). The whole group-two "stacks" above group-one no matter what happens inside.

Group One (z-index: 1)
Pink (z: 9999)
Group Two (z-index: 2)
Blue (z: 1)

🧠 Lesson: z-index competes only within the same stacking context. Setting an ancestor's z-index can trap children inside.
